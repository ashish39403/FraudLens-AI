# AI-Powered Fraud Investigation and AML Operations Platform

This is a portfolio-grade, production-oriented learning project for building a fraud investigation and AML operations platform for digital banking and fintech use cases.

The project is currently in **Phase 1: Problem Discovery and PRD**.

No implementation code should be added until the Phase 1 product scope is reviewed and approved.

## Current Documents

- `docs/PRD.md`: Phase 1 product requirements document.
- `docs/USER_JOURNEYS.md`: Practical user journeys for analysts, reviewers, managers, and AI-assisted report drafting.
- `docs/architecture/ARCHITECTURE.md`: Phase 2 high-level architecture.
- `docs/architecture/LOW_LEVEL_DESIGN.md`: Phase 3 low-level design.
- `docs/architecture/DATA_MODEL.md`: Phase 3 database entity design.
- `docs/architecture/API_CONTRACTS.md`: Phase 3 REST API contract draft.
- `docs/architecture/adr/`: Architecture decision records.

## Project Goal

Build a system that helps fraud and AML teams review suspicious activity faster by collecting evidence, explaining risk indicators, supporting human decisions, and keeping an audit trail.

The system should not pretend to replace human compliance judgment. High-risk decisions must remain human-controlled.

## Learning Goal

By the end of the project, the builder should be able to explain:

- The product problem.
- The backend architecture.
- The database model.
- The API contracts.
- The security model.
- The AI/ML design choices.
- The testing strategy.
- The deployment and monitoring setup.
- The trade-offs behind major decisions.

19. Resume and GitHub portfolio.

## Important Constraint

All business-impact numbers must be measured, estimated, or clearly marked as assumptions. The project must not use fake claims such as unmeasured percentage reductions in fraud or investigation time.
